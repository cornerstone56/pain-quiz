# 라온한의원 통증 문진

환자에게 보여주는 통증 자가 체크 페이지입니다. 주소는 [https://cornerstone56.github.io/pain-quiz/](https://cornerstone56.github.io/pain-quiz/) 입니다.

화면에 나오는 한글은 모두 `src/texts.json` 한 파일에 있습니다. 문장만 바꿀 때는 이 파일만 고치면 됩니다.

효과나 완치를 약속하는 말은 넣지 마세요. 지금처럼 “참고용”, “상담” 안내로 두세요. 환자 이름, 증상 기록, 연락처 같은 개인정보도 이 저장소에 올리지 마세요.

## 글만 바꾸기 (GitHub 웹사이트에서)

프로그램을 설치하지 않아도 됩니다.

1. 이 저장소의 `src/texts.json` 파일을 엽니다.
2. 오른쪽 위 연필 아이콘(**Edit this file**)을 누릅니다.
3. 바꾸고 싶은 한글만 수정합니다. 콜론(`:`) **왼쪽**의 영문 이름과 중괄호(`{name}` 같은 것)는 그대로 둡니다.
4. 아래 **Commit changes**를 누릅니다. 메시지는 “문구 수정”처럼 짧게 적어도 됩니다.
5. 저장소 **Actions** 탭에서 “Deploy to GitHub Pages”가 초록색이 되면 위 주소의 페이지가 새 문구로 바뀝니다. 브라우저에서 안 바뀌면 새로고침을 한 번 더 누르세요.

예시입니다. 시작 화면 제목을 두 줄로 두고 싶을 때입니다.

```json
"title": "나에게 맞는<br>통증 치료 찾기"
```

줄바꿈은 `<br>` 또는 `\n` 으로 씁니다. 둘 다 화면에서 줄바꿈으로 보입니다.

```json
"description": "첫 번째 문장입니다.\n두 번째 문장입니다."
```

쉼표와 따옴표는 JSON 문법입니다. 한글 문장 앞뒤의 `"` 는 지우지 말고, 문장 안 줄 끝의 쉼표도 함부로 지우지 마세요. 저장 후 페이지가 갱신되지 않으면, 그 파일의 직전 저장본으로 되돌린 뒤 다시 조금만 고쳐 보세요.

부위 이름(`areas.labels`)은 `오른쪽 어깨(앞)`처럼 적어 둡니다. `오른쪽` / `왼쪽`, 부위 이름, `(앞)` / `(뒤)` 모양을 유지하면 결과 카드에서 “양쪽”, “앞·뒤”로 합쳐 보여 줍니다. 부위 단어만 바꾸는 것은 괜찮습니다. 예: `오른쪽 어깨(앞)` → `오른쪽 어깨죽지(앞)`.

`오른쪽`, `왼쪽`, `앞`, `뒤`, `양쪽` 단어 자체를 바꾸려면 `areas.format` 안의 같은 단어도 같이 바꾸세요.

기간 버튼의 글(`2주 이내` 등)은 바꿔도 됩니다. `under2w`, `1to3m` 같은 왼쪽 이름은 결과 계산에 쓰이므로 바꾸지 마세요.

## 배포는 자동입니다

`main` 브랜치에 변경이 들어가면 GitHub Actions가 사이트를 만들어 [GitHub Pages](https://cornerstone56.github.io/pain-quiz/)에 올립니다. 따로 서버를 켜거나 비밀번호를 넣을 필요는 없습니다.

진행 상황은 저장소의 **Actions** 탭에서 “Deploy to GitHub Pages”가 초록색이 됐는지로 확인합니다.

### 이 변경을 처음 합친 뒤에 한 번만 할 일

지금 Pages는 `main` 브랜치의 파일을 그대로 공개하고 있습니다. 소스로 바꾼 뒤에는 배포 주체를 Actions로 바꿔야 새 사이트가 올라갑니다.

1. 이 풀 리퀘스트를 `main`에 병합합니다.
2. 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 바꿉니다.
3. **Actions** 탭에서 “Deploy to GitHub Pages”가 실패해 있으면 **Re-run** 으로 다시 실행합니다. 초록색이 되면 됩니다.
4. [https://cornerstone56.github.io/pain-quiz/](https://cornerstone56.github.io/pain-quiz/) 를 열어 시작 화면이 보이는지 확인합니다.

병합 직후, Source를 바꾸기 전에는 주소가 잠시 비어 보일 수 있습니다. Source를 GitHub Actions로 바꾼 뒤 워크플로가 성공하면 다시 열립니다. 그 다음부터는 `texts.json`만 고치고 커밋하면 같은 주소가 자동으로 갱신됩니다.

## 기능 수정을 AI에게 맡기기

버튼 추가, 질문 순서, 화면 구성처럼 글 이외의 변경은 AI에게 저장소 주소와 원하는 내용을 알려 주면 됩니다. 아래처럼 물어보면 됩니다.

```text
https://github.com/cornerstone56/pain-quiz 저장소를 수정해 줘.
결과 화면 아래에 진료 예약 안내 문장을 추가해 줘.
효과나 완치를 약속하는 표현은 넣지 마.
환자에게 보이는 글은 src/texts.json에 넣어 줘.
```

AI에게 맡길 때 같이 알려 주면 좋은 점입니다.

- 어느 화면인지 (시작, 질문, 결과)
- 버튼/문장의 정확한 한글
- 환자 개인정보나 비밀 값은 넣지 말 것
- 의료 효과를 단정하지 말 것

## 개발용 명령

로컬에서 화면을 보려면 Node.js가 필요합니다.

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:5173/pain-quiz/` 를 엽니다. 배포와 같은 결과물을 만들려면 `npm run build` 입니다. 만든 파일은 `dist/`에 생기며, 이 폴더는 저장소에 올리지 않습니다.
